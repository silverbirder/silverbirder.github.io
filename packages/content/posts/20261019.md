色々やることを達成できたので、数ヶ月前に書きかけたUIに関する本の執筆を再開しました。  
執筆をはじめて1週間ぐらいするのですが、**本を書くことで知識の整理になること** を改めて良さを実感しました。  

## やったこと

書きたいなと思うことを、色々なインプットとして Codex に渡しました。  

- 過去の私のブログ記事URL
- メモレベルの書きたい内容

私の書く文章の癖は、これまでの私のブログ記事を渡せばそれっぽい感じになります。  
まあ結局は読みにくい（おい！）ので、別のトーンを参考にしましたが...笑  

入力を終えると、どういうコンセプトとして本を書くのか芯を考えます。  
「AI 時代における UI をデザインする価値について」みたいなことを入れつつ、  
全体の構成を仮決めします。  
あとは、私の下書きレベルの残念文章を Codex に渡して文章を書かせます。  
AI ぽい文章ばかりになるので、結局はほとんど全て書き直していますが、  
話の筋としては良かったので骨格は残しつつ肉付けをひたすら微調整します。  

## よかったこと

技術ブログを書く時と同じですが、本の場合は書く量が違います。  
何度も文章を考えて微調整をしていくと、  

- 「これって、どういう意味だろう？」
- 「完全理解したぞ...！」
- 「わかった気になっていただけ...」
- 「これって、どういう意味だろう？」

を何度も何度もループします。  
これを繰り返すだけで、**自身の書きたかった知識が整理されていく** のが実感できました。  
また調べていく過程で、知らないことを知ることも増えたりします。  
Codex に情報ソースURLを貰って理解を深め、  
私なりの言語化をアウトプットして指摘を貰って、  
不明点は Codex に図示してもらったりすることで、  
ドンドンと知識が身についていく感覚があります。  

Codex のおかげで、UI というテーマ性で画面の図示をする機会が多く、  
そのUIのサンプル図も生成してもらい、100%一発では上手くいかない（自分もわかっていない）ので、  
10~20回ぐらい繰り返して完成します。  
全体に影響する修正において、Codex に全箇所いっきに修正してもらえるので、  
楽になったなぁと思います。  

## サポートに徹する

基本的に、私がペンを持ち Codex がサポートに徹するというスタンスにしています。  
書きたいと思う文章を本当に荒削りで良いので書いた上で、  
それを Codex に清書してもらいつつ サンプル画面作成や下調べ（脚注など）、  
テーブルやリスト形式の図示などをさせます。  

1. 私が原案を書く
2. Codex が訂正して本のプレビュー
3. 私が読んでフィードバックする
4. 2に戻る

何度も何度も繰り返して、形になっていきます。  
昔に書いた本の時と繰り返すことは変わりませんが、その繰り返す速度は圧倒的に早くなりました。  
Codex に先んじて10〜20ぐらいのチャットを送りつけてレスポンスを待っているうちに、  
さらに10〜20ぐらいのチャットを送るを何度もしていました。  

よくなかったのは「私の原文なしに文章をCodexに書かせること」でした。  
AIっぽい文章ができるのは当たり前ですが、無味無臭の文章を読んでも得られることがゼロばかりで、  
基本的にそれは禁止していました。  
方向性を決めるためのアイデアだしとしても、バイアスがかかってしまうので強制的にしないようにしました。  

## 終わりに

まだ全体の2割ぐらいしか終わっていません。  
これは完成するのか不安ですが、もし完成したらまたお知らせします！
