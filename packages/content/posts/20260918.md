個人開発、趣味としてのアプリ開発において費用をできる限り抑えたいです。  
特に課題になるのが DB選定です。  
もう耳にタコができるぐらい色々な人が書いていると思いますが、私も書きます。  

## 前提

趣味レベルのDB性能で十分です。  
データ容量、処理速度、その他諸々 特に求めることはありません。  
レート制限もある程度気にしません。  
ただただ、安くデータを永続的に保存できればそれでヨシです。  
私の作るものとして、Web アプリを前提とします。  

## スプレッドシート as a DB

Google スプレッドシートにデータを保存する方法です。  
Google スプレッドシートへの参照書き込むできるAPIが存在する（はず）ので、  
それをクライアントとして使用します。  

また似たようなサービスとして、Amazon Athena では S3 にCSVやJSONなどを置いて、  
読み書きすることができます。  

## オブジェクトストレージ as a DB

Dropbox や Google Drive などのオブジェクトストレージにデータを保存する方法です。  
Dropbox は私が新卒の頃に個人で作ったWebアプリのDBとして使っていた不思議な方法です。（笑）  

## ブラウザ as a DB

DuckDB のように、ブラウザ上にデータを保存する方法です。  
以下は、Google アクティビティデータをブラウザに保存し分析するWebアプリです。  
（動くのかどうか不明です）  

https://actviz.vercel.app

外部通信したくないセンシティブなデータだったので、上記方法を選びました。  

## ソースコード as a DB

プログラムのソースコードに JSON ファイルなどとしてデータを保存する方法です。  
GitHub Gist などでも良いでしょう。  

## XaaS

Heroku や Fly.io などのアプリ実行環境とDBをまとめて提供する PaaS や、  
Supabase のような バックエンド機能としてDBを提供する BaaS、  
PlanetScale や Neon のような DB専用のサービスを提供する DBaaS、  
Vercel や Cloudflare のような DB を含めたサーバーレスなプラットフォーム、  
AWS や Google Cloud のようなインフラ基盤全般を提供するものなど、  
たくさんあります。  

無料枠があったりなかったり、DBの種類も様々です。  

## どれが良いか

趣味の範囲なのでなんだって良いのですが、  
突然の値上げが往々にしてあります。  
一部に依存せず分散した方が良いのでしょうが、面倒です。  
好きに選びましょう。  

## 終わりに

メモリーにデータ保存させたり、  
(家内Webサービス向けの) ラズパイをDBとしたり。  
皆さんは、何を選びますか？
